# 交代后事（handover）

当用户说「交代后事」「交接」「收尾」，或收到「上下文危险」类通知（如 dsh-context-guard 注入）时，执行以下流程。

## 流程

### 1. 确认

- 若由插件/通知触发：先用 ask_user_question 问「上下文已到危险区，是否现在交代后事？」（选项：现在交接 / 稍后 / 不交接）；
- 用户已明确要求时跳过询问。

### 2. 汇总三块内容

- **未完待办**：当前任务进展、卡点、下一步动作；
- **已完成事项**：本会话做成的事（关键成果 / 产出文件 / 结论）；
- **踩坑经验**：本次的关键教训与正确做法（每条：场景 → 问题 → 正确做法，≤150 字）。

### 3. 写交接文件（当前工作区）

- 新建或更新 `HANDOVER.md`：目标、当前状态、需保持不变的决策、精确路径/命令、未解决错误、**下一步唯一动作**；
- 未完待办并入 `UNFINISHED.md`（若已存在）。

### 4. 踩坑经验写入跨会话记忆（如可用）

- 用 `memory` 工具写入（track: agent，scope: workspace 或 user-global）；
- 写入会触发审批（GUI 或 QQ「同意 dsh-xxx」）——等待用户确认；被拒则不重试、不绕过。

### 5. 汇报

- 把交接摘要（待办 / 已完成 / 下一步）展示给用户；
- 若安装了通知插件（如 dsh-qq-notify），可主动发一条「📦 已交代后事，新窗口可继续」。

## 原则

- 交接文档要能被新会话直接接续：**不要粘贴整段旧对话**（会重现同样的上下文压力）；
- 精确路径/命令优先于模糊描述；
- 敏感信息（凭据、token、未脱敏会话内容）不写入交接文档。
